进行代码审查时，按以下四维逐一检查，并用【发现:严重程度】格式输出：

1. 正确性（Critical/High）
   - 逻辑分支是否遗漏边界条件；异常是否被捕获且处理合理
   - 资源（文件/连接/锁）是否在 finally 中释放
2. 健壮性（High/Medium）
   - 外部输入是否做类型与范围校验；空值/超时/网络抖动是否考虑
   - 并发场景是否存在竞态（共享可变状态是否加锁或线程安全）
3. 可读性（Medium/Low）
   - 命名是否自解释；是否存在魔法数字（应提取为常量）
   - 函数是否过长（建议 < 50 行）、职责是否单一
4. 性能（Medium/Low）
   - 是否存在无必要的重复计算（应缓存）；循环内是否做 IO
   - 是否使用了复杂度更高的算法（应优先 O(n) 以下方案）

输出模板：
  1) 【发现:严重程度】问题描述 → 建议修复方式
  2) 总结：共 N 个问题（Critical X / High Y / Medium Z / Low W）
